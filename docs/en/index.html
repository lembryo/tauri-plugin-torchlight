tauri-plugin-torchlight

A Tauri v2 plugin to control a smartphone's torch (flashlight): turn it on and off, set its brightness, query availability and current state, and react to torch changes coming from the system. Android and iOS.

View on GitHub Dual licensed MIT / Apache-2.0

Overview

This plugin exposes a small API for using the camera flash unit as a flashlight from a Tauri v2 mobile app. It ships as two packages: the Rust plugin with its commands, and typed JavaScript/TypeScript bindings.

  • On and off — setTorch(true) / setTorch(false).
  • Brightness — a 0.0–1.0 level, honoured on devices that support it (iOS, and Android 13+). Elsewhere the torch simply turns on at full power.
  • Availability — isAvailable() reports whether a camera with a real flash unit exists.
  • Current state — isEnabled().
  • Change events — onTorchModeChanged() keeps your UI correct when the OS, another app, or thermal limits change the torch.
  • Explicit desktop behaviour — a clear error instead of silently doing nothing.
Two packages
tauri-plugin-torchlight (crates.io) and tauri-plugin-torchlight-api (npm) are released together and always share the same version number.

Installation

Rust

cargo add tauri-plugin-torchlight

Or add it to src-tauri/Cargo.toml directly:

[dependencies]
tauri-plugin-torchlight = "1"

JavaScript / TypeScript

Optional but recommended — it gives you typed helpers instead of raw invoke calls.

npm install tauri-plugin-torchlight-api

Setup

Register the plugin in src-tauri/src/lib.rs:

fn main() {
    tauri::Builder::default()
        .plugin(tauri_plugin_torchlight::init()) // Add this line
        .run(tauri::generate_context!())
        .expect("error while running tauri application");
}

Then grant the permission in src-tauri/capabilities/default.json:

{
    "permissions": [
        "torchlight:default"
    ]
}
Android permissions
No CAMERA permission is required. The plugin uses CameraManager.setTorchMode, so there is no runtime permission prompt. The manifest only declares android.hardware.camera.flash with required="false", which keeps the app installable on devices without a flash unit (isAvailable() returns false there).

Quick start

import {
    setTorch,
    isAvailable,
    isEnabled,
    toggle,
    onTorchModeChanged,
} from "tauri-plugin-torchlight-api"

// Check support before showing a torch button.
if (await isAvailable()) {
    await setTorch(true)            // full brightness
    await setTorch(true, 0.5)       // half brightness where supported
    const lit = await isEnabled()   // -> true
    await toggle()                  // flips the current state, returns the new one
    await setTorch(false)           // off
}

// Stay in sync when the system changes the torch.
const listener = await onTorchModeChanged(({ enabled, available }) => {
    console.log("torch:", enabled, "available:", available)
})

// Later, when you are done:
await listener.unregister()

setTorch

function setTorch(enabled: boolean, level?: number): Promise<void>

Turns the torch on or off.

Parameter Type Description
enabledrequired boolean true turns the torch on, false turns it off.
leveloptional number Brightness in the 0.0–1.0 range. Used only when turning on, and only on devices that support brightness control. Out-of-range values are clamped; omitting it uses full brightness.

Rejects on devices without a torch and on desktop. See error handling.

isAvailable

function isAvailable(): Promise<boolean>

Whether the device has a controllable torch. On Android the plugin looks for a camera with a flash unit; on iOS it checks whether the default video device reports hasTorch. Always false on desktop.

Use it to decide whether to show a torch button at all.

isEnabled

function isEnabled(): Promise<boolean>

Whether the torch is currently lit. Always false on desktop.

Where the Android value comes from
On Android the value is served from a cache kept up to date by CameraManager.TorchCallback, registered when the plugin loads. Changes made by other apps or by the OS are therefore reflected.

toggle

function toggle(): Promise<boolean>

Flips the current state and returns the new one. It is a thin helper over isEnabled() followed by setTorch(), and cannot set a brightness — it always turns on at full power.

onTorchModeChanged

function onTorchModeChanged(
    handler: (payload: TorchModeChangedPayload) => void,
): Promise<PluginListener>

Registers a listener for torch changes coming from the system: another app taking the camera, thermal limits, or the OS turning the torch off.

The returned PluginListener comes from @tauri-apps/api/core. Always call unregister() when you are done.

const listener = await onTorchModeChanged(({ enabled, available }) => {
    setLit(enabled)
    setSupported(available)
})

// e.g. when the component unmounts
await listener.unregister()
Timing differs per platform
Android uses CameraManager.TorchCallback (onTorchModeChanged and onTorchModeUnavailable); iOS observes AVCaptureDevice.isTorchActive via KVO. Note that your own setTorch() calls also fire the event.

Type reference

interface TorchModeChangedPayload {
    /** Whether the torch is currently lit. */
    enabled: boolean
    /** Whether a torch is currently usable on the device. */
    available: boolean
}

Command list

These are the Tauri commands exposed by the Rust side. The JS bindings are a thin wrapper over them.

Command Arguments Returns
plugin:torchlight|torch { enabled: boolean, level?: number } void
plugin:torchlight|is_available — boolean
plugin:torchlight|is_enabled — boolean

register_listener and remove_listener are provided by Tauri itself for event subscription. They need permissions, but you never call them directly — onTorchModeChanged uses them internally.

Events

Event Payload
torchModeChanged { enabled: boolean, available: boolean }

Using raw invoke

You can skip the npm package entirely.

import { invoke } from "@tauri-apps/api/core"

await invoke("plugin:torchlight|torch", { enabled: true, level: 0.5 })

const available = await invoke("plugin:torchlight|is_available")
const enabled = await invoke("plugin:torchlight|is_enabled")

Subscribe to the event with addPluginListener:

import { addPluginListener } from "@tauri-apps/api/core"

const listener = await addPluginListener("torchlight", "torchModeChanged", (payload) => {
    console.log(payload.enabled, payload.available)
})

Permissions (capabilities)

torchlight:default includes these five:

  • allow-torch
  • allow-is-available
  • allow-is-enabled
  • allow-register-listener
  • allow-remove-listener

To be more restrictive, grant them individually as torchlight:allow-torch and so on. Each command also has a matching deny-* permission.

Events need two of them
onTorchModeChanged requires both allow-register-listener and allow-remove-listener.

A read-only configuration

To observe the torch without ever turning it on:

{
    "permissions": [
        "torchlight:allow-is-available",
        "torchlight:allow-is-enabled",
        "torchlight:allow-register-listener",
        "torchlight:allow-remove-listener"
    ]
}

init

pub fn init<R: Runtime>() -> TauriPlugin<R>

Builds the plugin; pass it to tauri::Builder::plugin(). On mobile it registers the native plugin (TorchlightPlugin on Android, init_plugin_torchlight on iOS); on desktop it registers the stub implementation.

TorchlightExt

To drive the torch from Rust, use the extension trait available on any Manager (such as AppHandle).

use tauri_plugin_torchlight::TorchlightExt;

#[tauri::command]
async fn blink(app: tauri::AppHandle) -> tauri_plugin_torchlight::Result<()> {
    if app.torchlight().is_available()? {
        app.torchlight().torch(true, Some(0.7))?;
        std::thread::sleep(std::time::Duration::from_millis(200));
        app.torchlight().torch(false, None)?;
    }
    Ok(())
}

is_enabled fn is_enabled(&self) -> Result<bool>

Error

pub enum Error {
    /// The native mobile plugin returned an error (mobile only)
    PluginInvoke(tauri::plugin::mobile::PluginInvokeError),
    /// No torch hardware exists on desktop (desktop only)
    Unsupported,
}

Error serializes to a string, so the JS side receives a human-readable rejection value. The desktop Unsupported message is:

torchlight is only supported on Android and iOS; this is a desktop platform

Support matrix

Feature Android iOS Desktop
On / off Yes Yes Error
Brightness API 33+ Yes Error
isAvailable Yes Yes Always false
isEnabled Yes Yes Always false
torchModeChanged Yes Yes Never fires

Android

  • On/off goes through CameraManager.setTorchMode.
  • Brightness uses turnOnTorchWithStrengthLevel on API 33 (Android 13) and later. A device whose FLASH_INFO_STRENGTH_MAXIMUM_LEVEL is 1 or less is treated as having no brightness control and falls back to a plain toggle.
  • A 0.0–1.0 level is mapped onto the device's 1..maxLevel range. The result is always at least 1, so setTorch(true, 0.0) does not turn the torch off.
  • The camera used is the first one whose FLASH_INFO_AVAILABLE is true (usually the rear one). If none is found, isAvailable() returns false and torch rejects.
  • No CAMERA runtime permission is needed.
  • Requires minSdk 23.

iOS

  • Uses AVCaptureDevice.default(for: .video), but only when it reports hasTorch.
  • Brightness uses setTorchModeOn(level:). When the level is 1.0 or above, AVCaptureMaxAvailableTorchLevel is used instead, because passing exactly 1.0 can throw.
  • Omitting level means full brightness. Out-of-range values are clamped.
  • Under thermal pressure the call can fail (for example AVErrorTorchLevelUnavailable) and the promise rejects.
  • Requires iOS 13 or later.
About Info.plist
Torch control does not need NSCameraUsageDescription. If your app also captures from the camera, follow that feature's own requirements.

Desktop

Desktop machines have no torch hardware, so the plugin is explicit rather than silently pretending to succeed.

  • setTorch() rejects with the Unsupported error.
  • isAvailable() and isEnabled() return false.

As long as you branch on isAvailable(), running on desktop during development will not break your UI.

Keeping the UI in sync

The torch can change for reasons outside your app. Read the initial state, then follow the event. 

import { useEffect, useState } from "react"
import { isAvailable, isEnabled, onTorchModeChanged, setTorch } from "tauri-plugin-torchlight-api"

export function TorchButton() {
    const [supported, setSupported] = useState(false)
    const [lit, setLit] = useState(false)

    useEffect(() => {
        let listener: { unregister: () => Promise<void> } | undefined
        let disposed = false

        ;(async () => {
            setSupported(await isAvailable())
            setLit(await isEnabled())

            const l = await onTorchModeChanged(({ enabled, available }) => {
                setLit(enabled)
                setSupported(available)
            })
            // Handle unmounting before registration finished
            if (disposed) await l.unregister()
            else listener = l
        })()

        return () => {
            disposed = true
            listener?.unregister()
        }
    }, [])

    if (!supported) return null

    return (
        <button onClick={() => setTorch(!lit)}>
            {lit ? "Turn torch off" : "Turn torch on"}
        </button>
    )
}

Working with brightness

There is no API to ask whether brightness control is supported. Passing a level is always safe: devices without support simply turn on at full power rather than failing.

// 30% where supported, full brightness elsewhere
await setTorch(true, 0.3)
level: 0 does not turn the torch off
setTorch(true, 0) means "turn on at the lowest possible brightness". To turn the torch off, always use setTorch(false).

To change brightness while the torch is already lit, call again with enabled: true and a different level.

await setTorch(true, 0.2)
await setTorch(true, 0.8) // changes brightness without turning off

Error handling

The main cases where setTorch() rejects:

Situation Message
Running on desktop torchlight is only supported on Android and iOS; this is a desktop platform
Device has no flash unit Torch is not available on this device
Android cannot access the camera The CameraAccessException message, or Camera access error
iOS fails to light the torch (thermal limits, etc.) Torch could not be used: ... 
try {
    await setTorch(true)
} catch (e) {
    // arrives as a string
    console.warn("could not turn the torch on:", e)
}

Prefer branching on isAvailable() up front over matching on message text.

Limitations

Not supported today
  • No built-in strobe or blink patterns — drive setTorch() from your own timer if you need them.
  • No API to query whether brightness control is supported (it falls back to full brightness).
  • No camera selection — the first camera with a flash unit is used.
  • On Android, brightness only works on API 33 and later.

Troubleshooting

The command fails with a permission error

Check that torchlight:default is listed in src-tauri/capabilities/*.json. If you use the event, you also need allow-register-listener and allow-remove-listener.

isAvailable() returns false

You are probably on a device without a flash unit, an emulator or simulator, or desktop. Verify on real hardware.

Brightness changes have no visible effect

Android 12 and earlier, and devices whose FLASH_INFO_STRENGTH_MAXIMUM_LEVEL is 1, do not support brightness control. Turning on at full power is the documented fallback.

The torch went off when I opened another app

Another app took the camera, or the OS turned it off. Subscribe to onTorchModeChanged to keep the UI correct.

Releases and versioning

tauri-plugin-torchlight on crates.io and tauri-plugin-torchlight-api on npm are published together under the same version number. A push to main triggers the GitHub Actions workflow that publishes both; versions that already exist are skipped.
