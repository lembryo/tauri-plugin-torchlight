tauri-plugin-torchlight

Tauri v2 アプリからスマートフォンのライト（トーチ）を制御するプラグイン。点灯・消灯、明るさ調整、利用可否と現在状態の取得、そしてシステム側でライトが変化したときのイベント通知に対応します。Android と iOS 向けです。

GitHub で見る MIT / Apache-2.0 デュアルライセンス

概要

このプラグインは、Tauri v2 のモバイルアプリからカメラのフラッシュユニットを「懐中電灯」として使うための最小限の API を提供します。Rust 側のコマンドと、型付きの JavaScript/TypeScript バインディングの 2 つのパッケージで構成されます。

  • 点灯・消灯 — setTorch(true) / setTorch(false)。
  • 明るさ調整 — 0.0〜1.0 の範囲で指定。対応端末（iOS、および Android 13+）でのみ有効で、非対応端末では単純に最大輝度で点灯します。
  • 利用可否の判定 — isAvailable()。フラッシュユニットを実際に持つカメラがあるかどうかを返します。
  • 現在状態の取得 — isEnabled()。
  • 端末の能力の取得 — capabilities()。ハードウェアの有無、いま使えるかどうか、明るさ調整が実際に効くかどうかをまとめて返します。
  • アトミックな反転 — toggle(level?)。読み取りと書き込みをネイティブ側でまとめて行います。
  • 変化イベント — onTorchModeChanged()。OS や他アプリ、発熱制限によってライトが消えた場合でも UI を追従させられます。
  • 構造化されたエラー — すべての reject は kind を持つ TorchlightError です。メッセージ文字列で分岐する必要はありません。
  • デスクトップでの明示的な挙動 — 黙って何もしないのではなく、はっきりとエラーを返します。
2 つのパッケージ
Rust 本体の tauri-plugin-torchlight（crates.io）と、JS/TS バインディングの tauri-plugin-torchlight-api（npm）は同じバージョン番号で同時にリリースされます。

インストール

Rust 側

cargo add tauri-plugin-torchlight

src-tauri/Cargo.toml に直接書く場合:

[dependencies]
tauri-plugin-torchlight = "1"

JavaScript / TypeScript 側

型付きヘルパを使うためのバインディングです（必須ではありませんが推奨。使わない場合は invoke を直接呼びます）。

npm install tauri-plugin-torchlight-api

セットアップ

プラグインを src-tauri/src/lib.rs で登録します。

fn main() {
    tauri::Builder::default()
        .plugin(tauri_plugin_torchlight::init()) // この行を追加
        .run(tauri::generate_context!())
        .expect("error while running tauri application");
}

続いて src-tauri/capabilities/default.json で権限を付与します。

{
    "permissions": [
        "torchlight:default"
    ]
}
Android の権限について
CAMERA 権限は不要です。プラグインは CameraManager.setTorchMode を使うため、実行時パーミッションの要求は発生しません。マニフェストには android.hardware.camera.flash を required="false" として宣言しているだけなので、フラッシュのない端末にもインストールできます（その端末では isAvailable() が false を返します）。

クイックスタート

import {
    setTorch,
    isAvailable,
    isEnabled,
    capabilities,
    toggle,
    onTorchModeChanged,
} from "tauri-plugin-torchlight-api"

// ライトのボタンを出す前に、そもそも使えるかを確認する。
if (await isAvailable()) {
    await setTorch(true)            // 最大輝度で点灯
    await setTorch(true, 0.5)       // 対応端末では半分の明るさ
    const lit = await isEnabled()   // -> true
    await toggle(0.5)               // 現在状態を反転し、反転後の状態を返す
    await setTorch(false)           // 消灯
}

// 明るさスライダーを出してよいかを判定する。
const caps = await capabilities()
if (caps.brightnessSupported) {
    // caps.levelSteps は段階数（iOS は連続値なので null）
}

// システム側でライトが変わったときに追従する。
const listener = await onTorchModeChanged(({ enabled, available }) => {
    console.log("torch:", enabled, "available:", available)
})

// 不要になったら解除する
await listener.unregister()

setTorch

function setTorch(enabled: boolean, level?: number): Promise<void>

ライトを点灯・消灯します。

引数 型 説明
enabled必須 boolean true で点灯、false で消灯。
level任意 number 明るさ（0.0〜1.0）。点灯時、かつ明るさ調整に対応した端末（brightnessSupported が true）でのみ使われます。範囲外の値は 0.01〜1.0 にクランプされ、NaN や Infinity は「明るさ指定なし」として扱われます。省略時は最大輝度です。

ライトを持たない端末や、デスクトップでは reject されます。詳しくはエラーハンドリングを参照してください。

isAvailable

function isAvailable(): Promise<boolean>

端末がライトのハードウェアを持っているかを返します。これは端末の静的な性質で、アプリの実行中に変化することはありません。Android ではフラッシュユニットを持つカメラを探し、iOS では既定のビデオデバイスが hasTorch かどうかを見ます。デスクトップでは常に false です。

ライトのボタンを表示するかどうかの判定に使ってください。「いま使えるか」を知りたい場合は capabilities() の usable、または onTorchModeChanged の available を見てください。

isEnabled

function isEnabled(): Promise<boolean>

現在ライトが点いているかどうかを返します。デスクトップでは常に false です。

Android での取得元
Android の値は CameraManager.TorchCallback で更新されるキャッシュから返します。プラグインの load 時にコールバックを登録するため、他アプリや OS による変更も反映されます。キャッシュは torch() / toggle() の成功直後にも更新されるため、非同期のコールバックを待たずに正しい値が返ります。

capabilities

function capabilities(): Promise<TorchCapabilities>

この端末のライトで「実際に何ができるか」をまとめて返します。明るさスライダーなどの UI を出すかどうかは、isAvailable() ではなくこちらで判断してください。

フィールド 型 説明
available boolean ライトのハードウェアがあるか。静的な値で、実行中に変化しません。
usable boolean いまライトを使えるか。他アプリがカメラを掴んだときや発熱制限下では false になり、解消すると true に戻ります。
brightnessSupported boolean level が実際に明るさを変えるか。iOS では常に true。Android では API 33 未満の端末と、強度レベルを 1 段階しか報告しない端末で false です。
levelSteps number | null 明るさの段階数。Android で明るさ調整に対応している場合のみ数値になります。iOS（連続値）と非対応時は null です。
available と usable は別物です
available は「ハードウェアが存在する」、usable は「いま動かせる」という意味です。brightnessSupported が false の端末でも level を渡すこと自体は失敗しません（最大輝度で点灯します）。 
const { available, brightnessSupported, levelSteps } = await capabilities()

// 効かないスライダーを表示しない
if (available && brightnessSupported) {
    showBrightnessSlider({ steps: levelSteps ?? undefined })
}

デスクトップでは 4 つのフィールドがすべて「ライトなし」（false と null）で返り、エラーにはなりません。

toggle

function toggle(level?: number): Promise<boolean>

現在の状態を反転し、反転後の状態を返します（true なら点灯）。点灯側に倒れる場合は level で明るさも指定できます。level の扱いは setTorch() と同じです。

読み取りと書き込みはアトミックです
反転はネイティブ側で行われます。Android は synchronized ブロック、iOS は直列の DispatchQueue で保護されているため、同時に呼ばれた 2 つの toggle() が同じ開始状態を見ることはありません。

onTorchModeChanged

function onTorchModeChanged(
    handler: (payload: TorchModeChangedPayload) => void,
): Promise<PluginListener>

システム側でライトの状態が変わったときに呼ばれるリスナを登録します。他のアプリがカメラを掴んだ場合、発熱制限がかかった場合、OS が消灯した場合などに発火します。

戻り値の PluginListener は @tauri-apps/api/core の型です。不要になったら必ず unregister() を呼んでください。

デスクトップでも登録は成功し、イベントが発火しないだけです（プラグインが no-op の register_listener / remove_listener を提供しています）。プラットフォームごとの分岐は不要です。

const listener = await onTorchModeChanged(({ enabled, available }) => {
    setLit(enabled)
    setSupported(available)
})

// コンポーネントの破棄時などに
await listener.unregister()
発火タイミングはプラットフォームで異なります
Android は CameraManager.TorchCallback（onTorchModeChanged / onTorchModeUnavailable）を、iOS は AVCaptureDevice の isTorchActive と isTorchAvailable 両方の KVO を使います。どちらのプラットフォームも、消灯中に利用可否だけが変わった場合（発熱制限など）にイベントを 1 回発火します。イベントが伝えるのはあくまで「変化」です。プラグインのロードはリスナ登録より前に走り、そこで発火したイベントは届かないため、初期値は isEnabled() / capabilities() で読んでください。自分で setTorch() や toggle() を呼んだ場合にもイベントが発火する点に注意してください。

型リファレンス

interface TorchModeChangedPayload {
    /** ライトが現在点いているか。 */
    enabled: boolean
    /** ライトが「いま」使えるか（ハードウェアの有無ではありません）。 */
    available: boolean
}

interface TorchCapabilities {
    /** ライトのハードウェアがあるか。静的な値。 */
    available: boolean
    /** いまライトを使えるか。実行中に変化します。 */
    usable: boolean
    /** level が実際に明るさを変えるか。 */
    brightnessSupported: boolean
    /** 明るさの段階数。連続値（iOS）や非対応時は null。 */
    levelSteps: number | null
}

type TorchErrorKind =
    | "unsupported"    // デスクトップ：ライトのハードウェアがない
    | "unavailable"    // この端末に使えるライトがない
    | "cameraAccess"   // カメラにアクセスできない（Android）
    | "torchFailed"    // 点灯できなかった（発熱制限など）
    | "internal"       // それ以外：IPC、シリアライズ、プラグインの不具合

class TorchlightError extends Error {
    readonly kind: TorchErrorKind
}

コマンド一覧

Rust 側で公開されている Tauri コマンドです。JS バインディングはこれらを呼び出しているだけです。

コマンド 引数 戻り値
plugin:torchlight|torch { enabled: boolean, level?: number } void
plugin:torchlight|toggle { level?: number } boolean
plugin:torchlight|is_available — boolean
plugin:torchlight|is_enabled — boolean
plugin:torchlight|capabilities — TorchCapabilities
plugin:torchlight|register_listener { event: string, handler: Channel } void
plugin:torchlight|remove_listener { event: string, channelId: number } void

プラグインが宣言するコマンドはこの 7 つです。イベント購読に使う register_listener / remove_listener はモバイルでは Tauri のモバイルランタイムが、デスクトップではこのプラグインの no-op スタンドインが処理します。権限の対象にはなりますが、アプリから直接呼ぶ必要はありません（onTorchModeChanged が内部で使います）。

イベント

イベント名 ペイロード
torchModeChanged { enabled: boolean, available: boolean }

invoke で直接呼ぶ

npm パッケージを入れずに使うこともできます。

import { invoke } from "@tauri-apps/api/core"

await invoke("plugin:torchlight|torch", { enabled: true, level: 0.5 })

const available = await invoke("plugin:torchlight|is_available")
const enabled = await invoke("plugin:torchlight|is_enabled")
const caps = await invoke("plugin:torchlight|capabilities")
const next = await invoke("plugin:torchlight|toggle", { level: 0.5 })

この場合、reject される値は { kind, message } のオブジェクトです（npm パッケージはこれを TorchlightError に包み直しています）。

イベントを購読する場合は addPluginListener を使います。

import { addPluginListener } from "@tauri-apps/api/core"

const listener = await addPluginListener("torchlight", "torchModeChanged", (payload) => {
    console.log(payload.enabled, payload.available)
})

権限（capabilities）

torchlight:default には次の 7 つが含まれます。

  • allow-torch
  • allow-toggle
  • allow-is-available
  • allow-is-enabled
  • allow-capabilities
  • allow-register-listener
  • allow-remove-listener

個別に絞りたい場合は torchlight:allow-torch のように指定します。各コマンドには対応する deny-* もあります。

イベントを使うなら 2 つ必要
onTorchModeChanged は allow-register-listener と allow-remove-listener の両方を必要とします。

読み取り専用の構成例

点灯はさせず、状態の監視だけを許可する場合:

{
    "permissions": [
        "torchlight:allow-is-available",
        "torchlight:allow-is-enabled",
        "torchlight:allow-capabilities",
        "torchlight:allow-register-listener",
        "torchlight:allow-remove-listener"
    ]
}

init

pub fn init<R: Runtime>() -> TauriPlugin<R>

プラグインを構築します。tauri::Builder::plugin() に渡してください。モバイルではネイティブプラグイン（Android の TorchlightPlugin / iOS の init_plugin_torchlight）を登録し、デスクトップではスタブ実装を登録します。

ネイティブプラグインの登録は unwrap() しません。R8 による削除、古い AAR、パッケージ名の変更などで登録に失敗した場合は、セットアップ中にパニックするのではなくエラーが呼び出し元に伝播します。

デスクトップでは register_listener / remove_listener の no-op 実装も併せて登録するため、addPluginListener が「command not found」で reject することはありません。

TorchlightExt

Rust 側からライトを操作したい場合は、Manager を実装した型（AppHandle など）に生えている拡張トレイトを使います。トレイト自体のメソッドは fn torchlight(&self) -> &Torchlight<R> の 1 つだけで、実際の操作は返り値のハンドルが提供します。 

use tauri_plugin_torchlight::TorchlightExt;

#[tauri::command]
async fn blink(app: tauri::AppHandle) -> tauri_plugin_torchlight::Result<()> {
    if app.torchlight().is_available()? {
        app.torchlight().torch(true, Some(0.7))?;
        std::thread::sleep(std::time::Duration::from_millis(200));
        app.torchlight().torch(false, None)?;
    }
    Ok(())
}
メソッド シグネチャ
torch fn torch(&self, enabled: bool, level: Option<f64>) -> Result<()>
is_available fn is_available(&self) -> Result<bool>
is_enabled fn is_enabled(&self) -> Result<bool>
toggle fn toggle(&self, level: Option<f64>) -> Result<bool>
capabilities fn capabilities(&self) -> Result<TorchCapabilities>

クレートは Error、Result、TorchCapabilities、 TorchRequest、ToggleRequest、AvailabilityResponse、 EnabledResponse、および定数 MIN_LEVEL（0.01）を再エクスポートしています。

Error

#[non_exhaustive]
pub enum Error {
    /// モバイルのネイティブプラグインがエラーを返した（mobile のみ）
    PluginInvoke(tauri::plugin::mobile::PluginInvokeError),
    /// デスクトップにはハードウェアが存在しない（desktop のみ）
    Unsupported,
}

impl Error {
    /// 機械可読な識別子（"unsupported" / "unavailable" /
    /// "cameraAccess" / "torchFailed" / "internal"）
    pub fn kind(&self) -> String;
    /// 人間向けのメッセージ
    pub fn message(&self) -> String;
}

バリアントはプラットフォームごとに分かれているため、この enum を match する側は _ のアームを用意するか、cfg(mobile) / cfg(desktop) でアームを切り分ける必要があります。#[non_exhaustive] はそれを明示し、将来のバリアント追加に備えるためのものです。

Error は { "kind": "...", "message": "..." } としてシリアライズされ、JS 側では TorchlightError に包まれて届きます。デスクトップの Unsupported は次の文言です。

torchlight is only supported on Android and iOS; this is a desktop platform

対応状況

機能 Android iOS デスクトップ
点灯・消灯 対応 対応 エラー
明るさ調整 API 33+ 対応 エラー
isAvailable 対応 対応 常に false
isEnabled 対応 対応 常に false
toggle 対応 対応 エラー
capabilities 対応 対応 すべて false
levelSteps API 33+ null（連続値） null
torchModeChanged 対応 対応 登録は成功・発火しない

Android

  • 点灯・消灯は CameraManager.setTorchMode。
  • 明るさは API 33（Android 13）以上で turnOnTorchWithStrengthLevel を使用。FLASH_INFO_STRENGTH_MAXIMUM_LEVEL が 1 以下の端末は明るさ調整に非対応と判定し、通常の点灯にフォールバックします。
  • 0.0〜1.0 の値は端末の 1..maxLevel に丸められます。結果は必ず 1 以上になるため、setTorch(true, 0.0) でも消灯はしません。 levelSteps はこの maxLevel です。
  • 対象カメラは、フラッシュユニット（FLASH_INFO_AVAILABLE）を持つカメラのうち背面（LENS_FACING_BACK）のものを優先して選びます。背面が見つからない場合はフラッシュを持つ最初のカメラにフォールバックします。cameraIdList の順序だけに頼ると、マルチカメラ端末でフラッシュ付きの前面カメラや補助カメラを選んでしまうことがあるためです。どのカメラも見つからない場合は isAvailable() が false を返し、torch は reject します。
  • toggle() の読み取り・書き込みは synchronized(torchLock) の中で行われます。
  • キャッシュした点灯状態は torch() / toggle() の成功時にその場で更新されます。TorchCallback はメインルーパー上に非同期で届くため、待っていると成功直後の isEnabled() が古い値を返してしまうからです。
  • load() で TorchCallback を登録すると、その時点の状態が 1 回届きます。これがキャッシュの初期値になるため、点灯したままアプリを起動しても isEnabled() が正しい値を返します。このとき発火するイベント自体は捨てられます（load() は WebView がリスナを登録するより前に走るため）。
  • TorchCallback は onDestroy で解除されます。プロセススコープのシングルトンに登録されるため、解除しないと Activity がリークし、再生成されたプラグインが二重にイベントを発火します。
  • CAMERA 実行時権限は不要です。
  • minSdk 23 が必要です。

iOS

  • AVCaptureDevice.default(for: .video) のうち hasTorch が真のデバイスを使用します。
  • 明るさは setTorchModeOn(level:)。level が 1.0 以上のときは、例外を避けるため AVCaptureMaxAvailableTorchLevel を使います。
  • level 省略時、および非有限値のときは最大輝度（1.0 扱い）。範囲外の値は TorchMath.minLevel（0.01）〜1.0 にクランプされます。
  • setTorchModeOn(level: 0.0) は Objective-C の NSInvalidArgumentException を送出し、Swift の do/catch では捕捉できずプロセスが落ちます。そのため下限を minLevel で切り、Android と同じ「0 は可能な限り暗く、消灯ではない」という契約に揃えています。
  • toggle() の読み取り・書き込みと lockForConfiguration は直列の DispatchQueue 上で行われます。
  • イベントは isTorchActive と isTorchAvailable の両方を KVO で監視します。load() 時の発火は行いません（リスナ登録前なので届かないため）。iOS は状態を毎回デバイスから直接読むので、キャッシュの初期化も不要です。
  • 明るさは連続値なので levelSteps は常に null、 brightnessSupported は常に true です。
  • 発熱制限下では AVErrorTorchLevelUnavailable などで失敗することがあり、その場合は reject されます。
  • iOS 13 以上が必要です。
Info.plist について
トーチ制御にカメラの使用許可（NSCameraUsageDescription）は不要です。ただし同じアプリ内でカメラ撮影も行う場合は、そちらの要件に従ってください。

デスクトップ

デスクトップにはハードウェアのライトがないため、黙って成功したふりをするのではなく明示的に振る舞いを分けています。

  • setTorch() と toggle() は Unsupported（kind: "unsupported"）で reject されます。
  • isAvailable() と isEnabled() は false を返します。
  • capabilities() は { available: false, usable: false, brightnessSupported: false, levelSteps: null } を返します。
  • onTorchModeChanged() は登録に成功し、イベントが発火しないだけです。

したがって、開発中にデスクトップで動かしても isAvailable() で分岐しておけば UI が壊れることはありません。

UI を状態と同期する

ライトは自分のアプリ以外の要因でも変化します。初期状態を読み、以降はイベントで追従するのが基本形です。

import { useEffect, useState } from "react"
import { isAvailable, isEnabled, onTorchModeChanged, setTorch } from "tauri-plugin-torchlight-api"

export function TorchButton() {
    const [supported, setSupported] = useState(false)
    const [lit, setLit] = useState(false)

    useEffect(() => {
        let listener: { unregister: () => Promise<void> } | undefined
        let disposed = false

        ;(async () => {
            setSupported(await isAvailable())
            setLit(await isEnabled())

            const l = await onTorchModeChanged(({ enabled, available }) => {
                setLit(enabled)
                setSupported(available)
            })
            // 登録完了前にアンマウントされた場合に備える
            if (disposed) await l.unregister()
            else listener = l
        })()

        return () => {
            disposed = true
            listener?.unregister()
        }
    }, [])

    if (!supported) return null

    return (
        <button onClick={() => setTorch(!lit)}>
            {lit ? "ライトを消す" : "ライトを点ける"}
        </button>
    )
}

明るさを扱う

level はいつ渡しても安全です。非対応端末では単に最大輝度で点灯するだけで、エラーにはなりません。

// 対応端末では 30% の明るさ、非対応端末では最大輝度で点灯する
await setTorch(true, 0.3)

ただし「効かないスライダー」を出さないために、UI を組み立てる前に capabilities() を見てください。

const caps = await capabilities()
if (caps.brightnessSupported) {
    // levelSteps が数値なら、その段階数に合わせたスライダーにできる
    showBrightnessSlider({ steps: caps.levelSteps ?? undefined })
}
level: 0 は消灯ではありません
setTorch(true, 0) は「点灯し、この端末で可能な限り暗くする」という意味です。これは Android と iOS で共通の契約で、0 が「消灯」になることはありません。消したいときは必ず setTorch(false) を使ってください。範囲外の値は 0.01〜1.0 にクランプされ、NaN や Infinity は「明るさ指定なし」＝最大輝度として扱われます。

点灯中に明るさだけを変えたい場合は、enabled: true のまま別の level で再度呼びます。

await setTorch(true, 0.2)
await setTorch(true, 0.8) // 消さずに明るさだけ変更

エラーハンドリング

この API の関数は、reject するとき必ず TorchlightError を投げます。Error を継承しているので e instanceof Error も真になり、kind で機械的に分岐できます。

import { setTorch, TorchlightError } from "tauri-plugin-torchlight-api"

try {
    await setTorch(true)
} catch (e) {
    if (e instanceof TorchlightError) {
        switch (e.kind) {
            case "unsupported":
                // デスクトップ。ボタン自体を出さないのが正解
                break
            case "unavailable":
                toast("この端末にはライトがありません")
                break
            case "cameraAccess":
                toast("カメラを使用中の他のアプリを閉じてください")
                break
            case "torchFailed":
                toast("ライトを点けられませんでした（端末が高温かもしれません）")
                break
            case "internal":
                console.error(e.message)
                break
        }
    } else {
        throw e
    }
}

setTorch() / toggle() が reject する主なケースと、対応する kind は次のとおりです。

状況 kind メッセージ
デスクトップで実行した unsupported torchlight is only supported on Android and iOS; this is a desktop platform
フラッシュのない端末 unavailable Torch is not available on this device
Android でカメラにアクセスできない cameraAccess CameraAccessException のメッセージ、または Camera access error
点灯に失敗した（発熱制限など。Android / iOS 共通） torchFailed iOS は Torch could not be used: ...、Android は例外のメッセージ、または The torch could not be used
権限（ACL）が足りない、IPC の失敗、プラグインの不具合 internal Tauri が返す文字列

メッセージ本文は人間向けで、安定した API ではありません。分岐には必ず kind を使い、そもそも事前に isAvailable() や capabilities() で判定しておくのが最善です。

制限事項

現時点で未対応
  • ストロボ／点滅パターンの組み込み機能はありません。必要なら setTorch() を自前のタイマーで呼んでください。
  • Android で明るさを指定できるのは API 33 以上のみです。

トラブルシューティング

コマンドが権限エラーになる

src-tauri/capabilities/*.json に torchlight:default を追加したか確認してください。イベントを使う場合は allow-register-listener と allow-remove-listener も必要です。

isAvailable() が false を返す

フラッシュユニットのない端末、エミュレータ、シミュレータ、またはデスクトップで実行している可能性があります。実機で確認してください。

明るさを変えても見た目が変わらない

Android 12 以前、または FLASH_INFO_STRENGTH_MAXIMUM_LEVEL が 1 の端末では明るさ調整に対応していません。仕様どおり最大輝度で点灯します。capabilities() の brightnessSupported で事前に判定できます。

他のアプリを使ったらライトが消えた

カメラを掴んだ他アプリや OS による消灯です。onTorchModeChanged を購読していれば UI を追従させられます。

リリースとバージョン

crates.io の tauri-plugin-torchlight と npm の tauri-plugin-torchlight-api は同じバージョン番号で同時に公開されます。main への push をトリガーに GitHub Actions が両方を公開し、すでに公開済みのバージョンはスキップされます。

公開前にテストゲートが走ります。cargo clippy --all-targets -- -D warnings、 cargo test、npm run build、そして Cargo.toml と package.json のバージョンが一致しているかのチェックです。いずれかが失敗すると公開は行われません。

公開順は npm が先、crates.io が後です。npm は 72 時間以内なら unpublish できるのに対し、crates.io の yank は公開の取り消しにはならないため、この順序なら片方だけ公開された状態で失敗することがありません。
